# Adaptive Lesson Design｜適性課程設計（提案）

> 狀態：待審核的設計規格；這份文件不是新 Core，也不代表教材生成器已實作。  
> 適用：Lesley Teaching Engine 後續的英語教案、講義、學習單、練習及複習設計。  
> 上位依據：`LESLEY_TEACHING_ENGINE_v2.4_STABLE.md`。若本提案與 Stable Core、核准單元範圍或正式教材內容衝突，以既有權威為準。

## 1. 一句話原則

**先判斷學生要學會什麼、需要哪種支持，再選活動；不為了湊齊模板而增加任務。**

Look & Find、Noun Detective、One or Many / Choose、Brain Check 是**可選活動庫**，不是每單元必須依序出現的四個步驟。學習地圖、插圖、角色引導員、心智圖及題數也都不是強制配置。

活動可以 **1 個、2 個或數個**，也可以改用其他更貼合目標的形式；評估依據是學習證據與學生負荷，不是模組完整率。

## 2. 不可省略的品質界線

彈性只影響**教學呈現與活動選擇**，不得降低以下要求：

- **來源治理**：原始／正式課本優先；先通過 Source Readiness、內容範圍與詞彙來源檢核。缺口足以影響正式題目時，狀態為 BLOCKED，只報缺口，不假裝出正式題本。
- **教學目標**：每個保留的活動，必須明確服務某項已核准的學習目標或證據需求。
- **題目有效性**：答案可判定、詞彙可追溯、視角清楚、沒有未教內容或答案洩漏。
- **證據分層**：觀察、引導練習、規則回憶、獨立應用、遷移與延後提取不能混為一談。
- **真正獨立**：有目標相關提示的成功不能判為獨立掌握；撤除提示後須用**未曝光的新題**重測。延後穩定仍需適當延後、無提示、新題證據。
- **版本一致**：學生／教師／答案由同一題目對照資料產生；正式發布仍須通過原有 Release QA 與 Quality Review。

**少活動不等於少證據。** 核心能力若尚未得到足夠、可信的證據，就不能因教材短而直接判定學會。

## 3. 課程決策順序

| 步驟 | 教師／產生器要判斷 | 輸出 |
|---|---|---|
| 1. 鎖定來源 | 本次核准的課本、單元、詞彙、已教與未教範圍是什麼？ | 來源與範圍狀態（READY／READY WITH LIMITS／BLOCKED） |
| 2. 選定目標 | 本課最需要學生**理解、辨識、提取、應用或遷移**哪項能力？ | 精簡的目標與成功證據 |
| 3. 判斷障礙 | 困難是知識、詞形、語意、閱讀、視角，還是任務執行負荷？有何可信證據？ | 支持路線與尚待驗證的假設 |
| 4. 選最少必要活動 | 哪種任務最直接練到目標、又不添加無關負荷？ | 活動組合、順序、作答空間 |
| 5. 檢查學習證據 | 哪些是引導練習？何時撤除提示？用什麼新題重測？ | 練習／獨立檢核分界與後續複習計畫 |
| 6. 檢查出版品質 | 題目、答案、字型、灰階、留白、分頁及手機／iPad 可讀性是否一致？ | 可審核的 Student／Teacher／Answer 交付物 |

若只有活動設計需求，可只做相應部分；**不因為表格有六步，就把每次低風險任務擴寫成六個教學模組**。

## 4. 活動是工具，不是章節配額

| 學習目標／單元特性 | 可優先考慮 | 無需勉強加入 |
|---|---|---|
| Starter：主格代名詞與 be 動詞配對 | 主詞對照、最小例句、角色辨識、短句填空、新題轉換 | 不相關的名詞複數偵探 |
| Starter：姓名與年齡問答 | 說話者／答話者角色卡、問句選擇、簡短對話 | 為了視覺效果而添加大量插圖 |
| Unit 1：人物、親屬與職業 | 家族關係圖、Who 問句、身分資訊判讀 | 不提供關係證據的裝飾圖 |
| Unit 2：Where 與位置 | 明確物件數量及位置的空間圖、資訊差、口述定位 | 無法唯一判斷遠近／位置的圖 |
| 單字拼字或發音 | 聲音切分、拼讀、逐步撤除線索、無提示提取 | 每字都強制製作助記故事 |
| 閱讀理解 | 文章分段、回文定位、證據標記、句子與推論問答 | 與閱讀目標無關的分類活動 |
| 已穩定掌握的內容 | 縮短重複練習，加入有意義的新情境 | 只為增加題數而換名詞重出同型題 |

以上是**活動匹配示例，不是教材內容的核准宣告**。真正出題時仍須核對當前正式來源與學生已學紀錄。

### 四個原活動的定位

- **Look & Find**：適合「需要從證據看出差異」的主題；不是每課都要觀察圖。
- **Noun Detective**：適合真正需要名詞辨識、分類、比較與規則歸納的目標；不把非名詞主題硬改名詞探究。
- **One or Many / Choose**：適合單複數、主詞－動詞搭配等選擇性應用；對非數量目標可改為 Fill / Transform / Explain。
- **Brain Check**：適合情境判斷與理由說明；若目標是精準拼字或基礎提取，可換成無提示產出。

不強制保留活動的英文名稱，更不強制用這四個名稱當每頁標題。

## 5. ADHD／閱讀障礙友善：調整方式，不推測能力

- 分成可預測的小任務；每次只凸顯當前步驟，允許必要時短暫休息。
- 文字短而明確，但**不把「每句一律少於 15 字」當成高於語意清楚的硬限制**。
- 關鍵字加粗、閱讀字體清晰、行距與作答區足夠；灰階影印仍能分辨題意。
- 裝飾插畫及擬人角色屬**可選支持**。若無助理解或反而提高負荷，就不放。
- 降低**非目標**的視覺、抄寫與操作負荷；不可藉此降低目標文法、拼字或閱讀標準。
- 允許教師朗讀非評量目標指令；如朗讀會直接洩漏閱讀檢核答案，須改列為有支持的練習。
- 紀錄「需提示才開始／中途返回任務」和「英文規則會不會」為不同訊號；不以診斷名稱推論個別學生表現。

## 6. 可用於後續產生器的最小設計資訊

未來若實作教材生成器，每次輸入／審核至少要讓教師看懂：

1. **本課來源與限制**：哪些內容已核實？哪些尚未確認？
2. **本課目標**：要學生完成何種認知動作？
3. **活動選擇理由**：為何用比較圖、對話、閱讀、拼字或其他形式？
4. **支援安排**：哪些提示可在教學時使用？何時撤除？
5. **證據方式**：哪一題是新題獨立檢核？如何安排適切的後續提取？
6. **交付狀態**：草稿／待核對／可發行，不把範例或測試成功稱為正式釋出。

產生器**不應預設四個活動欄位皆必填**；也不應僅以「四個任務全部完成」作為通過條件。

## 7. 實作與驗收情境（文件提案，不代表程式已完成）

| 情境 | 預期行為 |
|---|---|
| 輸入只有 Starter 主詞與 be 動詞 | 只選最有用的主詞對照與應用／獨立檢核，不強制名詞偵探 |
| 輸入 Unit 1 家庭關係 | 優先家族圖與 Who 問答，必要時才增加觀察或生活遷移 |
| 輸入 Unit 2 位置 | 圖示須能唯一支持答案，避免指涉不明 |
| 輸入閱讀文章 | 以文本證據為中心，不必額外製作「One or Many」 |
| 來源缺少關鍵頁或學生未教範圍不可證 | 標示限制或 BLOCKED；不得包裝成正式可用的新題 |
| 學生在提示下答對 | 只記錄有支持的成功，提示撤除後須用新題複查 |
| 原本只需兩個活動即可達到目的 | 不補到四個；但保留必要的獨立證據規劃 |

## 8. 本提案不修改的內容

- **不修改** `index.html`、`service-worker.js`、PWA 學生紀錄、弱點儀表板或資料儲存格式。
- **不取代** Active Core v2.4 Stable，也不自行變更 Mastery、Gate、Source Authority 或 Release QA。
- **不新增**真實學生姓名、健康診斷、測驗資料或私密教材掃描到公開 GitHub。
- **不聲稱**已實作自動教材選擇、個別化演算法或通過真實課堂成效驗證。

> **驗收重點**：當某個活動對目標沒有幫助時，系統應有充分理由**不選它**；當必要的學習證據不足時，也不能為了精簡而省略檢核。
