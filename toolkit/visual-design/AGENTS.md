# 視覺設計工具庫：後續助理選用規則

## 範圍與權限
本文件只規範 `toolkit/visual-design/` 及明確引用它的任務。不覆寫 repository 既有指示，不變更 Teaching Engine 的教學邏輯、Gate、教材來源限制或驗收規則。

使用者希望之後按需求推薦對應工具，不必重新貼八個專案名稱。接到相關任務且能讀取本工具庫時，先讀 README.md 與來源鎖定／驗證記錄，再選最少必要工具。此文件是 GitHub 中的持久記錄，不等於聊天記憶已寫入；不能聲稱每個新對話一定會自動載入它。

## 需求對應
- 手繪框線、草圖、學習筆記：Rough.js。
- 心智圖、概念關係、工作流程：Mermaid；需要手繪外觀時才另評估 Rough.js，不能宣稱原生 3D。
- 表單、按鈕、頁籤、卡片、可操作前端：shadcn/ui；先檢查框架相容，不為使用元件而強制重寫既有單檔 PWA。
- 背景、文字、邊線、深淺主題色階：Radix Colors；不與 Radix Primitives 混淆，實際對比仍須驗證。
- 品牌標誌：Simple Icons；不是所有通用 icon 或教材插圖來源，先確認官方品牌聲明。
- 字體來源及配置：Fontsource；按語言、字集、字重、授權取用官方來源，不從執行環境打包分享字體檔。
- README 徽章：Markdown Badges；只標示真實版本與狀態。
- GitHub 活動統計卡：原 GitHub README Stats 僅備查；官方已宣告不再維護。需要新部署時重新查驗其官方指向的延續專案，不在沒有核對的情況下自行替換。它不適合當一般教學成績、案件或營收儀表板。

## 交付方式
對使用者用繁體中文，先給可開啟的結果與白話用途。手機／iPad 使用不應要求本機 Node.js、終端機或桌面 Git 操作。沒有實作就不能把操作說明稱為交付；沒有實際開啟或測試就不能宣稱手機相容。

將以下狀態分開：來源已核對、原始碼已下載、依賴已安裝、功能已整合、已部署、功能與介面已實測。CRC／雜湊只能驗證檔案，不是完整資安、功能或相容性測試。

## 正式整合時
1. 先確認任務、資料來源、輸出格式及現有技術架構；已知資訊不要重問。
2. 依用途提出一個主要工具，必要時再加一至兩個輔助工具；不要把八套全灌入每個專案。
3. 查官方文件與目前維護狀態，選相容且可追溯的發行版本。不要把來源庫 HEAD 當成穩定版承諾。
4. 先讀再改，使用独立分支；非明確授權不得合併 main、改部署、重写既有教學程式。
5. 保留授權及來源；程式與視覺產物不放客戶、學生、帳戶或秘密金鑰資料。
6. 視需求測試中文顯示、手機寬度、觸控、列印／匯出、載入失敗及無障礙。測過哪些就報告哪些。
7. 更新實際使用紀錄；尚未用過的工具維持備用，不宣稱已融入日常工作流程。

GitHub Actions 壓縮包有保存期限；來源 commit／網址與下載驗證記錄須留在本資料夾。更新工具不自動等於更新正式應用。不建立定時追蹤或外部服務，除非使用者明確要求。
